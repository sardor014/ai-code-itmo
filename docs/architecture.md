# Архитектура проекта

Проект строится на принципах чистой архитектуры (Clean Architecture) для обеспечения простоты будущего расширения (добавление БД и интеграции с внешними API).

## Компоненты

### 1. Frontend (Клиентская часть)
- Отвечает за отображение формы ввода и результата.
- Взаимодействует с Backend через REST API.

### 2. Backend (Серверная часть)
Реализован с использованием многослойной архитектуры:

- **Слой представления (Presentation / API Layer):**
  - Принимает HTTP-запросы от Frontend.
  - Осуществляет валидацию форматов данных.
- **Слой бизнес-логики (Domain / Service Layer):**
  - Содержит правила валидации предметной области (этаж <= этажности дома, жилая площадь < общей).
  - Вызывает слой инфраструктуры для получения оценки.
- **Слой инфраструктуры (Data / Infrastructure Layer):**
  - Реализует доступ к данным через ORM (SQLAlchemy).
  - Содержит логику "заглушки" (mock) для модели оценки.
  - **Репозиторий (Repository):** Отвечает за сохранение результатов в PostgreSQL и поиск существующих записей по параметрам.

### 3. База данных (Persistence Layer)
- **PostgreSQL:** Используется для хранения истории расчетов.
- **Таблица `calculations`:** Хранит входные параметры (этаж, площадь и т.д.), результат оценки и метку времени (timestamp).

## Логика работы с кэшем и БД
Для обеспечения чистоты архитектуры, бизнес-логика (Service Layer) координирует процесс:
1. Запрашивает у репозитория расчет с аналогичными параметрами.
2. Если расчет найден и его возраст < 30 дней — возвращает сохраненное значение.
3. В противном случае — инициирует новый расчет и сохраняет его в БД через репозиторий.

## Стек технологий (Обновленный)
- Backend: Python (FastAPI), SQLAlchemy (Async), PostgreSQL.
- Frontend: HTML/CSS/JS.
- Тестирование: pytest, Playwright, Allure, **Testcontainers** (для тестирования БД).
