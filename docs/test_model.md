# Тестовая модель и Тест-дизайн

## Тестовая модель
Тестирование разделено на уровни (пирамида тестирования):
1. **Unit-тесты (pytest):** Тестирование моковой логики расчета и функций валидации.
2. **Integration-тесты (pytest):** Проверка API-ендпоинтов (HTTP-запросы и ответы).
3. **E2E-тесты (Playwright):** Имитация действий пользователя в браузере (заполнение формы, отправка, проверка UI).

## Тест-дизайн сценариев (Параметры квартиры)

### Позитивные сценарии
1. **Стандартная квартира:** Ввод всех валидных параметров (например: этаж 5, этажность 10, комнат 2, общая 50, жилая 30).
2. **Граничные значения:**
   - Этаж = 1 (первый этаж).
   - Этаж = Этажность (последний этаж).

### Сценарии работы с базой данных и кэшем
1. **Сохранение в БД:** После первого расчета запись должна успешно появиться в таблице `calculations`.
2. **Получение из кэша (хит):** Повторный запрос с теми же параметрами в течение 30 дней не должен приводить к пересчету (возвращается старое значение из БД).
3. **Пересчет по истечении срока (мисс):** Запрос с теми же параметрами, но для записи старше 30 дней, должен инициировать новый расчет и обновить запись/создать новую.
4. **Изоляция в Testcontainers:** Проверка того, что тесты базы данных проходят в изолированном контейнере PostgreSQL.
